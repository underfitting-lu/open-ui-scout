# Contributing

Thanks for helping improve Open UI Scout.

## Add A New GitHub UI Resource

Before adding a repository, check:

- The repository exists at the stated owner/name.
- The license is clear and compatible with common open-source or commercial frontend use.
- The repository has enough recent activity or stability for the intended category.
- The stack is clear, such as React, Next.js, Vue, Nuxt, Svelte, Astro, Tailwind, CSS, or native mobile.
- The usage notes explain when the resource fits and when it should be avoided.
- The resource does not duplicate an existing entry unless it belongs in another category for a clear reason.

## Fix A Broken Or Moved Repository

If a repository is archived, renamed, transferred, deleted, or no longer maintained, update the resource pool and note the replacement when one exists.

## Add A Style Mode

Include:

- the type of products it fits
- visual traits
- candidate sources
- anti-patterns

Keep style modes broad and reusable. Do not add a style mode for one private project.

## Add A Page Type

Include:

- the expected user workflow
- relevant UI states
- possible base UI and pattern sources
- implementation cautions

## Pull Request Checklist

- Check license, repo activity, stack fit, and usage notes for new resources.
- Keep the skill suitable for public sharing.
- Avoid turning Open UI Scout into a single project template.
- Keep recommendations compatible with the "at most 3 primary UI sources" rule.
- Update `README.md` or `AUDIT.md` only when the public guidance or audit status changes.
